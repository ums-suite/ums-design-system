# @ums/design-system

The shared Angular 22 UI kit and design-token package consumed by all six UMS front-ends
(`ums-public-web`, `ums-admission-web`, `ums-student-web`, `ums-faculty-web`, `ums-admin-web`,
`ums-alumni-web`) per [ADR-0017](https://github.com/ums-suite/ums-platform/blob/main/docs/adr/0017-shared-design-system-package.md).
Full spec: [`ums-platform/docs/client/design-system/requirement-spec.md`](https://github.com/ums-suite/ums-platform/blob/main/docs/client/design-system/requirement-spec.md),
[`design-decisions.md`](https://github.com/ums-suite/ums-platform/blob/main/docs/client/design-system/design-decisions.md),
[`edge-cases.md`](https://github.com/ums-suite/ums-platform/blob/main/docs/client/design-system/edge-cases.md).

## Consuming this package

Install the pinned version from the platform's private registry:

```bash
npm install @ums/design-system
```

**Components** — import from the package root, never from a deep/internal path:

```ts
import { UmsButtonComponent, UmsIconComponent, ThemeService } from '@ums/design-system';
```

**Styles** — a consuming app's global stylesheet loads, once:

```scss
// Token-driven CSS custom properties (light/dark, both @media (prefers-color-scheme) and
// [data-theme] override). Load as a plain stylesheet, never @use'd into the Sass module graph.
@import '@ums/design-system/styles/tokens.css';

// Hand-authored partials: Google Fonts loading (Fraunces/Inter/Noto Sans+Serif Bengali), a
// minimal reset, and a couple of token-backed utility classes (.ums-tnum, .ums-visually-hidden).
@use '@ums/design-system/styles/index' as ums;
```

**Typed tokens** — for the rare case a component needs a token value in TypeScript (never a raw
`var(--...)` string literal — the consumption-contract lint rules below block that):

```ts
import { Tokens } from '@ums/design-system';
el.style.setProperty('fill', Tokens.color.primary); // "var(--color-primary)"
```

## Token layers

Primitive → semantic → component (`requirement-spec.md` §7). Only **semantic** tokens are ever
public — color, type, space, radius, shadow, motion, ease, and bp — built from three synchronized
outputs generated by `tools/tokens/build-tokens.mjs` from the JSON source under
`tools/tokens/source/`:

1. `styles/tokens.css` — CSS custom properties (`--color-primary`, `--space-4`, ...), light/dark
   via `@media (prefers-color-scheme)` and an explicit `[data-theme]` override, plus a
   `[data-register="operational"]` variant for `ums-admin-web`/`ums-faculty-web`'s calmer type
   register (`requirement-spec.md` §2 Principle #4).
2. `styles/_tokens.scss` — the same values as SCSS variables (compile-time only).
3. `tokens/tokens.generated.ts` — the typed `Tokens.*` map, each entry a `"var(--...)"` string.

A component's own internal styling always resolves to these tokens, never a hardcoded value
(`requirement-spec.md` §6) — the mechanism that keeps a future palette/spacing revision a
one-file change instead of a six-repo find-and-replace.

## Versioning & consumption contract (`requirement-spec.md` §9)

- **Non-breaking addition** (a new token, a new component, a new variant) → **minor** version.
- **Any change to an existing token's meaning/value or a component's public API** → **major**
  version. A consuming app's upgrade is a deliberate, tested action, never a silent visual
  regression on its next unrelated deploy.
- **Backport policy**: a security or accessibility fix is backported to the last minor of each
  major line a live app still depends on — an app is never forced to take an unrelated breaking
  change just to receive a critical patch.
- **Deprecated token aliases** (`tools/tokens/deprecated-aliases.json`) keep a renamed token
  resolving under its old CSS custom-property name for a full major-version cycle
  (`design-decisions.md` "Token Versioning & Deprecation Policy").
- **Lint-enforced consumption contract**: this package ships an ESLint rule
  (`tools/eslint-rules/no-raw-design-token-css-var.js`) and a Stylelint rule
  (`tools/stylelint-rules/no-raw-design-token-css-var.js`), both named
  `ums/no-raw-design-token-css-var`, that block a raw `var(--color-*)`/`var(--shadow-*)`/...
  reference outside this package's own token source. A consuming app configures both the same
  way `projects/catalog` does in this repo's `eslint.config.js`/`.stylelintrc.json` (the catalog
  app stands in for a real `ums-*-web` app for this purpose) — always go through a component or
  the typed `Tokens.*` map instead.
- **Release gate**: a visual regression suite (Playwright, screenshot diffing against
  `projects/catalog`, this package's "Storybook-equivalent catalog") plus an automated a11y scan
  (axe-core) run in this package's own CI on every change, before publish — see `../../e2e/`.

## Local development

```bash
npm install              # also runs tokens:build + icons:build (postinstall)
npm start                # serves the catalog app at http://localhost:4300 (builds the lib first)
npm run test             # design-system unit tests (Karma + Jasmine, headless Chrome)
npm run build             # builds design-system, then catalog
npm run e2e               # Playwright: axe-core a11y + visual regression against the catalog app
npm run e2e:update-snapshots  # regenerate visual-regression baselines after an intentional change
npm run changeset         # record a semver-intent changeset for the next release
```
